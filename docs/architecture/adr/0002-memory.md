# ADR 0002：Mem0 运行方式、嵌入模型与向量存储

- 决策日期：2026-10-27。
- 状态：D2 选型结论；随本 PR 评审、合并生效。三项均已有实施基线，未部署、未调用、未验证检索质量。
- 需求依据：[PRD V1.0](../../product/PRD-V1.0.md) 第 4.6、8.2、10、13 章；依赖 [ADR 0001](0001-stack-decisions.md)。

## 决策摘要

| 决策          | 结论                                                                              | 实施与验证状态                                     |
| ------------- | --------------------------------------------------------------------------------- | -------------------------------------------------- |
| Mem0 运行方式 | 自建 Mem0 OSS，采用 Node.js/TypeScript `mem0ai/oss`，由服务端 Memory Manager 封装 | 未接入；B-MEM0 验证                                |
| 嵌入模型      | OpenAI 官方 `text-embedding-3-small`，固定 1536 维                                | 未接通；B-EMBED 验证账号和中文召回                 |
| 向量存储      | PostgreSQL 16 + pgvector；同实例独立记忆数据库及专用角色                          | 当前仍为普通 PostgreSQL；B-VECTOR 验证扩展与持久化 |

## 1. 运行方式：Mem0 OSS 自建

### 决定

- 首期将 Mem0 TypeScript OSS 作为服务端依赖，在执行器所在 Node 进程内运行；通过自研 Memory Manager 暴露受控的写入、检索、编辑、禁用与删除接口。
- 不为记忆单独部署 Python HTTP 服务，也不引入 Mem0 Cloud、Qdrant、图数据库或重排服务。后续若隔离运行有明确收益，再将同一 Memory Manager 边界移到独立服务。
- Mem0 记忆提取 LLM 显式选用 Anthropic 官方 provider，模型与 ADR 0001 的 `claude-sonnet-5-5` 保持一致；提取是独立模型调用，单独计成本，不把 Claude Agent SDK 本身当成嵌入模型。
- 显式配置 LLM、embedder 和持久化 vectorStore，不使用 `new Memory()` 的隐式默认值。具体参数与版本在接入 PR 验证，不把 Python 配置字段直接复制到 TypeScript。
- Mem0 内部操作历史与业务审计分别处理。SDK 若使用本地 SQLite 历史，必须指定受控持久卷、限制文件权限，并覆盖备份、删除和恢复验证；不得遗留到临时工作目录或将原文视作永不清理的审计。

### 理由与取舍

官方 TypeScript OSS 已提供所需 LLM、嵌入和 pgvector 适配，能够沿用首期 Node.js 与 PostgreSQL。自建便于掌握检索索引、隔离规则、禁用和删除边界，代价是团队承担扩展安装、SDK 升级、备份及故障处理。

Mem0 Cloud 能减少运维，但本项目需要明确嵌入配置和数据删除边界；首期选择显式可控的 OSS。自建不代表数据完全留在本地：提取文本会发送给 Anthropic，嵌入文本会发送给 OpenAI。未完成账号、网络和发送数据范围核对前，只能用非敏感样例验证，不能宣称真实业务已可用。

## 2. 嵌入：text-embedding-3-small，1536 维

### 决定

- 通过 OpenAI 官方 Embeddings API，使用 Mem0 的 `openai` embedder；明确配置模型 `text-embedding-3-small`，以 1536 维建集合，并在接入时断言实际返回维度。
- 选择小型嵌入模型作为两人团队、中文短文案和偏好检索的初始基线，不宣称其中文效果已达到验收标准。B-EMBED 用固定中文样例检验同义表达、无关内容、账号隔离和长文本处理。
- 记忆写入与查询使用同一嵌入模型、维度及预处理版本；记录配置版本。更换模型或维度时新建集合、重建索引并验证后切换，禁止把不同模型的向量混写到原集合。
- 非空输入、长度与分块在 Memory Manager 校验；超限内容不能静默截断成改变原意的记忆。长文本先保存权威业务记录，再提取有来源的短记忆。
- 缺少 Key、额度、网络或嵌入失败时标记同步失败/待重试。不得改用随机向量、内存临时索引或另一模型而继续显示“同步成功”。

OpenAI 官方文档确认该模型默认输出 1536 维，并支持用于语义检索。`text-embedding-3-large` 暂不引入；如中文召回未达预先冻结的样例标准，记录失败案例后修订选型。Ollama/本地模型是存在外部发送限制时的另一个方向，不能未经重建和回归就作为透明降级。

## 3. 向量存储：PostgreSQL 16 + pgvector

### 决定

1. 保留 PostgreSQL 16 主版本；未来接入 PR 使用提供 pgvector 的同主版本构建（如官方扩展项目的 `pgvector/pgvector:pg16`），验证后锁定具体镜像 digest。此次不修改 Compose、不替换现有数据卷。
2. 同实例创建独立记忆数据库（计划名 `multi_agent_memory`）和专用运行角色，通过独立连接字符串提供给 Memory Manager。业务数据库继续由 Drizzle 管理；Mem0 角色不得修改业务库，业务角色不得读取 Mem0 私有历史。
3. 运维/迁移身份在目标记忆库安装并启用 `vector` 扩展；运行身份不授予超级用户。Mem0 所需建表权限仅限自己的 schema，集合参数显式指定 1536 维和版本化名称。
4. 首期采用精确向量检索，暂不启用 HNSW、IVFFlat 或 DiskANN。样本规模和延迟确有需要时，再评估索引与过滤召回；不引入额外扩展以提前优化。
5. 原有 `postgres:16` 健康、连接或读写检查通过，仅证明普通数据库就绪。必须另行验证 `vector` 扩展、目标数据库权限、Mem0 读写和重启后的向量数据保留。
6. 在副本上验证镜像切换和已有卷兼容后再接入；禁止为了启用 pgvector 删除 D1 数据卷。备份包括业务库、记忆库和内部历史，先恢复后验证同步一致性。

### 权威记录和同步规则

- PostgreSQL **业务库**保留任务事实、人工编辑、来源、记忆类型、当前版本、状态、确认依据与操作审计；Mem0/向量库是可重建检索索引，不参与审批授权。
- 业务写入先以事务保存事实及待同步记录，Memory Manager 异步应用到 Mem0，记录成功、失败、版本和外部记忆 ID。更新按业务记忆 ID/版本幂等处理，旧同步任务不能覆盖新版本。
- 检索显式限制团队、账号、允许类型和用途；返回结果后再与业务库当前版本/状态核对。跨库没有分布式事务，不能仅依赖向量 metadata 的旧状态决定可用性。
- 禁用/删除首先在业务库生效，立刻从业务检索结果排除；即使索引删除失败也不能继续注入上下文。物理清理及 Mem0 历史清理有独立同步状态和失败提示，不能提前宣布数据已全部删除。
- 候选经验默认不能进入创作/正式策略上下文；一次人工编辑不能自动升级为长期偏好，自动提取不能覆盖已确认规则。具体确认规则仍以 PRD 4.6 为准。
- Mem0 内部可能合并、更新记忆；接入时必须证明它不会跨团队/账号/候选状态修改已确认记录。无法保证时阻断该写入路径，改为经 Memory Manager 审核的显式写入，不以模型自动合并结果替代业务事实。
- 实验使用独立集合/命名空间与冻结配置，禁止污染业务记忆。普通任务与实验都记录实际采用的业务记忆 ID/版本。

同实例部署降低首期运维成本，但不是独立故障域；数据库故障可能同时影响业务和检索。未来负载或恢复要求超过此方案时，再拆实例，保持 Memory Manager 接口不变。

## 4. 实施前验证与负责方向

以下是待转 Issue 的验证清单，尚未在 GitHub 创建。负责人由对应接入 PR 的认领人承担；最迟在记忆实现 PR 合并及发送真实业务数据前完成，不因块 B 文档完成而关闭验证项。

| ID       | 负责方向      | 必须取得的证据                                                                                                                                    | 当前状态       |
| -------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| B-MEM0   | 记忆/后端     | 锁定 TypeScript OSS 版本；验证 add/search/update/delete、版本映射、候选隔离、提取 JSON、历史持久化与删除；停库/断网不会造成静默丢失或无限成功状态 | 未接入、未验证 |
| B-EMBED  | 记忆/模型接入 | 使用非敏感中文样例，确认模型和 1536 维输出；冻结相关/无关样例、召回标准后测试；记录 Token、费用来源、失败处理与数据发送范围                       | 未接通、未验证 |
| B-VECTOR | 后端/环境     | 原有业务卷数据保留；专用角色隔离；扩展可用；向量写入/查询、重启持久化、备份恢复通过；故障后重建连接及重新同步可复现                               | 未部署、未验证 |

模型、SDK、镜像和配置取值在实际验证后进入锁文件/配置快照；不在本文猜测当前账号的权限、免费额度或实测召回率。若官方提供方不可用，标记受阻并修订 ADR，不能把内存 mock 视作持久记忆验收。

## 5. 配置与实现范围

后续接入将新增独立的记忆数据库连接、OpenAI Key、嵌入模型/维度、Mem0 集合及历史路径配置，并沿用服务端 Anthropic Key。配置命名和合法值在实现 PR 中与 `.env.example` 一起加入；本次 `.env.example` 和运行代码仍保持 D1 状态。

业务部署位置、长期数据保留时限、外部供应商数据政策和灾难恢复指标仍需按 PRD 第 13 章落实。选定 pgvector 不代表这些事项也已完成。
