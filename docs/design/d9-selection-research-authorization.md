## 榜单与选题

1. 用户已核实当前 XXAPI 接口抓取每日热榜。页面按“XXAPI · GitHub 每日热榜”展示，采集时间单独记录，不推断供应商未返回的榜单更新时间、日界线或排名指标。
2. 无效候选过滤；同一仓库保留首条有效记录；显示过滤和去重警告。保留原始响应及原始顺序供回查。当前严格整榜失败的解析器须在后续实现时调整。
3. 不在选题页面增加“补充研究问题”输入框，只使用已有任务要求及六章研究方法。
4. 每个任务只选一个项目；选定后不支持改选，换项目需新建任务。
5. 每个 attempt 最多一份榜单快照，同 attempt 不刷新。这是项目的快照规则，不是“API 每天只能调用一次”。
6. 返回空数组时，标记暂无可用榜单数据，停止后续选题和研究，不自动重试；不能据此断言 GitHub 当日没有热门项目。

## 初次研究授权

“选定并深入研究”一次提交，在同一事务中锁定选题并创建待用研究授权；不能出现选题保存成功却漏建授权，或重复点击创建多份授权。沿用 Session、团队权限、任务版本、幂等键和归属校验。

- Supervisor 先判断任务要求。若仍需澄清，保留未消耗授权；答复后在同 attempt 重新判断。
- 真正通过 SDK 原生分派 Research 时，原子消耗本次授权；不能在点击选题时提前消耗，也不能恢复已经消耗的授权。
- 一次授权覆盖一轮研究，轮内允许多次受限模型和工具调用。授权不能授予通用命令、文件、其他 Agent 或发布能力。
- 首轮来源范围为当前仓库及已允许的三平台资料。GitHub 之外的其他官网、文档留到用户明确授权的补查阶段；README 外链不自动授予访问权。

## 研究失败与重新执行

研究执行失败结束整个 attempt。用户通过一个明确的“重新执行并授权研究”按钮，在同一事务中创建新 attempt 和新授权。

新 attempt 沿用原选题和原榜单作为选题依据，不重新抓榜；不复用旧研究报告，报告链从新版本 1 开始。旧尝试、报告、失败和授权记录保留。单次工具读取失败或合法 partial 报告不等同于整轮研究执行失败。

## 补充资料与补查

本批补资料入口支持粘贴文本、来源链接及用户一手资料确认，不包含文件上传。

- 用户选定报告中要补查的问题／缺口，再用一个“提交资料并授权补查”按钮完成材料登记与新授权创建。
- **允许没有新文本或链接，只针对选定问题明确授权再搜索一轮。** 材料不是补查的必填前提；明确的问题范围和用户授权是必需条件。
- 新授权绑定当前 attempt 最新采用的完整报告及补查范围，不能静默基于旧版本建立分支，也不能扩大到其他项目或无关目标。
- 补查仍由 Supervisor 原生分派 Research，并在实际分派时消耗新授权；不自动启动第二轮研究或恢复旧授权。
- 输出更新后的完整报告，保留原证据、记录新增／修正／撤回及缺口变化。历史版本不覆盖。
- 一手资料确认由后端记录确认人、时间和材料版本；材料正文或模型自报不能生成确认。报告注明“用户提供，未经外部独立核验”。

**访问授权仅本轮补查有效。** 下一轮须重新列出范围并由用户确认；不跨 attempt 或任务自动继承。历史报告和已登记证据继续按版本保留，历史链接或 README 链接不自动授予下一轮新的抓取权限。
