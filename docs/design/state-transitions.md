# D1 状态转换表

日期：2026-10-27。版本：0.1。本地设计初稿，待共同走查；以下转换是设计要求。D4 已实现模拟执行的启动、排队、逐步执行、成功/失败、待澄清阻断、停止及从头重试；澄清答复后的排队恢复也已接通（当前以非空答复为条件）；真实 Agent、语义充分性判断、审核与发布等其他转换仍待实现，实际范围见[任务接口说明](../infra/tasks.md)。

配套文档：[核心对象设计](domain-model.md)。需求依据：[PRD V1.0（核对版本 12f36ec）](https://github.com/a2440890770-max/multi-agent-ops/blob/12f36ec9432c920c4c8d5cdc9b5fd7f08ceb2cb5/docs/product/PRD-V1.0.md)。本文 R01—R12 对应配套文档中的已确认业务规则。

## 1. 状态维度及通用判定

| 维度 | 状态                                                       | 权威对象                                         |
| ---- | ---------------------------------------------------------- | ------------------------------------------------ |
| 执行 | 待澄清、排队中、执行中、待人工处理、产出就绪、失败、已取消 | ExecutionAttempt.status                          |
| 审批 | 未申请、待批准、已批准、已失效                             | 当前版本审核资格及 Approval 记录的投影           |
| 发布 | 未发布、待人工发布、发布中、发布待核实、已发布、发布失败   | 实际 PublishOperation.status；没有操作时为未发布 |
| 复盘 | 未触发、处理中、已完成、失败                               | Reflection；没有记录时为未触发                   |

补充状态：审核周期 queued / running / completed / failed / cancelled，审核结果 pass / changes_required / manual_required；Task.lifecycle 为 open / terminated / published，仅描述任务管理与发布终结；记忆及同步状态见第 7 节。各维度独立，审核通过不等于人工批准，批准不等于已发布，复盘失败不改变发布结果。

### 1.1 所有转换的共同要求

- 由服务端验证团队、当前角色、对象归属、当前版本、任务 revision 和前置条件；禁止只靠按钮禁用或客户端声明。
- 表中未列出的转换默认拒绝；失败时保持原状态并记录必要原因，不允许任意设置状态字段。
- 保存、批准、执行启动／取消、发布占锁等竞争操作在同一任务的一致性边界串行化；同时发生时只能有一个基于旧版本的操作成功。
- 外部结果必须匹配工作代次、操作、发送记录和目标版本。延迟回调不能覆盖人工新版本，也不能使旧批准重新有效。
- 页面、接口路径、错误码和数据库实现不在本文定义；“版本冲突”“发布锁定”等是拒绝原因类别。

### 1.2 操作锁

| 情形                                     | 编辑／保存               | 新执行／重试           | 提交审核／批准           | 实际发送                                 |
| ---------------------------------------- | ------------------------ | ---------------------- | ------------------------ | ---------------------------------------- |
| 待澄清或排队中                           | 禁止；先停止尝试         | 禁止重复启动           | 禁止                     | 禁止                                     |
| 执行中、取消待确认或人工审核排队／运行中 | 禁止                     | 禁止                   | 禁止重复提交或批准       | 禁止                                     |
| 产出就绪或待人工处理，无工作槽           | 可保存，保存后需手动审核 | 显式新建尝试时允许     | 依当前版本及审核结果判断 | 仅有效批准后由用户点击                   |
| 仅停止了本次执行，无工作槽且任务仍开放   | 可编辑                   | 可显式新建尝试         | 人工审核通过后可批准     | 仍须有效批准和点击发布                   |
| 任务已终止                               | 禁止，先显式重启         | 可显式新建完整尝试     | 禁止                     | 禁止                                     |
| 已批准但尚未点击发布                     | 可保存并使批准失效       | 可新建尝试并使批准失效 | 重复批准返回已有有效记录 | 点击发布时再次校验                       |
| 待人工发布／发布中／发布待核实           | 禁止                     | 禁止                   | 禁止变更发布资格         | 禁止重复发送；只允许回填／核实等收敛操作 |
| 发布失败且结果已明确                     | 可保存并使旧批准失效     | 可新建尝试             | 依当前版本重新判断       | 明确人工重试，禁止自动重发               |
| 已发布                                   | 原任务只读               | 原任务禁止             | 原任务禁止               | 原任务禁止；复制为新任务                 |

待人工发布也持有发布锁，这是对 R02 的工程补充：内容可能已被复制到外部，不能允许编辑后再把旧发布回填成新版本成功。

## 2. 执行尝试转换

完整尝试覆盖研究、初稿、自动审核及最多三轮修改。人工保存后的单独审核使用第 3 节的审核周期，不复活已经结束的尝试。

| 编号 | 当前状态 → 目标状态                     | 触发事件与前置条件                                     | 原子变更／后续行为                                                             |
| ---- | --------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------ |
| E01  | 无尝试 → 待澄清／排队中                 | 用户启动任务；任务开放、无工作或发布锁                 | 创建尝试、冻结输入及配置、取得工作槽；信息不足则待澄清，否则排队               |
| E02  | 待澄清 → 待澄清                         | 答复仍不足或存在关键冲突                               | 追加答复及缺失项，不生成、不发布                                               |
| E03  | 待澄清 → 排队中                         | 必要信息已补齐                                         | 保存澄清快照，等待领取                                                         |
| E04  | 排队中 → 执行中                         | 执行器取得有效租约；未取消                             | 记录开始时间、代次及步骤；先研究再生成和审核                                   |
| E05  | 执行中 → 待澄清                         | 发现无法合理推定的关键业务信息缺失                     | 保存证据及问题，停止后续生成；无在途步骤后等待答复                             |
| E06  | 执行中 → 执行中                         | 自动审核未通过；原尝试额度小于 3、无取消               | 原子预留下一修改轮次并加一；生成新版本、失效旧资格，再审核                     |
| E07  | 执行中 → 产出就绪                       | 当前版本审核通过或完成合法主观裁决，无确定性阻断       | 保存审核结论，结束周期和尝试，释放工作槽；等待人工批准，不自动发布             |
| E08  | 执行中 → 待人工处理                     | 第三轮后仍不通过，或遇到需人工解决的阻断               | 保存原因，结束自动循环，释放工作槽；不自动再生成                               |
| E09  | 排队中／执行中 → 失败                   | 非取消故障或确认进程中断                               | 记录错误；隔离旧执行器后释放工作槽，不自动从头重跑                             |
| E10  | 待澄清／排队中 → 已取消                 | 用户停止尝试，确认未领取或无在途工作                   | 记录取消及停止时间，撤销队列资格，释放工作槽                                   |
| E11  | 执行中 → 执行中                         | 请求停止本次执行                                       | 写取消意图，禁止调度新步骤，仍锁定编辑；不能立即释放工作槽                     |
| E12  | 执行中 → 已取消                         | 已停止或旧执行器已被隔离，不能再提交结果               | 写 stoppedAt、结束时间并释放槽；任务仍开放时可人工编辑                         |
| E13  | 旧尝试保持终态，新尝试 → 待澄清／排队中 | 用户重试／重新执行；旧尝试已停止，任务未发布，无发布锁 | 创建新 ID 和 attemptNo，从头执行；旧批准失效，清空当前内容和审核引用，保留历史 |

E13 中新尝试的计数从 0 开始，旧尝试计数和版本不变。“重试失败步骤”不属于首期；同一轮模型调用的有限技术重试复用轮次，不增加也不返还该轮额度。

### 2.1 停止执行与终止任务

| 事件                 | 前置条件                                   | 结果                                                                                 |
| -------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------ |
| 停止本次执行以便编辑 | 无实际发布锁                               | 发起 E10／E11；只有 E10／E12 完成后允许编辑；不自动终止任务                          |
| 终止任务             | 未进入实际发布交接／发送，无发布锁，未发布 | Task.lifecycle 置 terminated，批准失效，阻止后续发布；有运行工作时发出取消并等待确认 |
| 重启已终止任务       | 所有旧工作已停止，无发布锁、未发布         | 用户显式新建完整执行尝试，生命周期回到 open；不恢复旧批准                            |
| 终止与发布同时发生   | 在同一任务上原子比较资格                   | 终止先提交则禁止发送；发布占锁先提交则拒绝终止，进入回填／核实路径                   |

已发出的外部请求不能因取消而标记“未发布”。运行进程失联也不能单凭租约到期立即开放编辑：先隔离旧写入，再写入失败或已取消状态。

## 3. 保存、人工审核与修改额度

| 编号 | 当前情形                         | 事件与条件                             | 结果／拒绝行为                                                                              |
| ---- | -------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------- |
| C01  | 本地输入尚未保存                 | 用户输入或修改                         | 仅编辑缓冲区变化，不创建内容版本、不审核、不失效批准                                        |
| C02  | 可编辑，无锁                     | 点击保存；任务及内容版本与读取时一致   | 原子创建新版本、更新指针、清空审核资格、失效旧批准、递增 revision、写审计；不启动审核       |
| C03  | 版本已变化                       | 另一成员用旧 revision 或旧版本保存     | 整体拒绝，返回冲突原因；输入保留，刷新比较后才能另行保存                                    |
| C04  | 最新人工版本尚未提交             | 点击提交审核；任务开放、无工作或发布锁 | 取得人工审核工作槽，冻结目标版本，ReviewCycle 进入 queued；不创建新完整尝试、不重置三轮计数 |
| C05  | 审核 queued → running            | 有效执行器领取，未取消                 | 记录开始，维持编辑锁                                                                        |
| C06  | 审核 running → completed         | 目标版本仍有效；检查通过／合法裁决     | 写 pass 结论，释放工作槽，当前版本进入待批准                                                |
| C07  | 审核 running → completed         | 未通过或需补充证据                     | 写 changes_required／manual_required，释放工作槽，返回人工处理；不自动重写人工版            |
| C08  | 审核 queued／running → cancelled | 请求取消且已确认停止／隔离             | 保存取消原因，释放工作槽，无通过资格                                                        |
| C09  | 审核 queued／running → failed    | 审核故障、进程中断、输出结构无效       | 保存错误，确认隔离后释放槽；明确显示审核失败，不按通过处理                                  |
| C10  | 审核失败／未通过                 | 用户再次提交当前版本                   | 新建审核周期保留旧记录，额度不变；重新校验无工作和发布锁                                    |
| C11  | 自动生成产生新版本               | 有效代次、未取消，且轮次已预留         | 创建不可变版本、更新指针、失效旧审核和批准；旧回调或旧基版本提交被拒                        |

三轮上限约束的是完整尝试的自动修改轮次。达到上限后，仍可人工保存和提交审核；通过审核才进入批准，不因为“已人工编辑”直接获得批准资格。

## 4. 审批状态转换

审批状态针对当前内容版本显示。不存在独立“申请批准”按钮的强制要求：**当前版本审核通过后进入待批准**，用户再点击批准。本文据此消除初稿中的两种实现分支。

| 编号 | 当前状态 → 目标状态     | 触发事件与条件                                             | 数据变化／限制                                                    |
| ---- | ----------------------- | ---------------------------------------------------------- | ----------------------------------------------------------------- |
| A01  | 无内容 → 未申请         | 当前还没有内容或新尝试刚启动                               | 无有效审核和批准，不能发布                                        |
| A02  | 未申请／已失效 → 待批准 | 当前版本审核通过，无未解决阻断，任务开放                   | 关联通过的审核周期；不会创建发布操作                              |
| A03  | 待批准 → 已批准         | 有权限成员点击批准；版本稳定、无工作或发布锁、基础检查有效 | 创建绑定版本、摘要及账号的 Approval，写操作者和时间；等待点击发布 |
| A04  | 已批准 → 已批准         | 重复批准同一版本，资格仍有效                               | 返回已有有效批准，不重复创建发布操作                              |
| A05  | 已批准／待批准 → 已失效 | 保存新版本或新建完整执行尝试                               | 原子失效旧批准，撤销旧审核资格；新当前内容需手动审核              |
| A06  | 已批准／待批准 → 已失效 | 终止任务、原审核资格撤销或基础规则变更后不再满足           | 记录原因；必须重新审核／批准，不能静默恢复旧批准                  |
| A07  | 未申请／已失效 → 原状态 | 审核失败、未通过或仍有确定性阻断                           | 禁止批准；模型高分或人工主观裁决不能绕过权限、格式及事实处理要求  |

新版本若替代了已批准或待批准版本，当前投影显示已失效，直到新版本审核通过；首次草稿未申请过批准时显示未申请。旧批准始终绑定旧版本，不能改绑新版本。

## 5. 发布状态转换

### 5.1 发送前共同检查

点击发布或人工重试都必须重新检查：权限及账号授权、任务开放、当前内容版本／摘要、有效批准、审核与基础规则、无取消意图、无运行工作、无其他未决发布、无既有成功发布。任一不符均拒绝，不调用外部服务。

创建／复用稳定发布操作、占用发布锁和冻结发送信息必须原子完成。PRD“批准后立即发布”已由 R05 更新：批准动作不能触发实际发送。

| 编号 | 当前状态 → 目标状态                     | 事件与前置条件                                     | 数据变化／限制                                                                 |
| ---- | --------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------ |
| P01  | 未发布 → 发布中                         | 用户点击官方发布，共同检查通过                     | 复用／创建唯一操作，创建发送记录并占锁；持久化后才调用官方能力                 |
| P02  | 未发布 → 待人工发布                     | 用户点击人工发布，共同检查通过                     | 创建人工交接记录，冻结批准文案并占锁；展示可复制版本及回填要求                 |
| P03  | 发布中 → 已发布                         | 收到明确成功，核对账号、发送记录及内容             | 保存平台 ID／链接和确认方式，Task.lifecycle 置 published；原任务不再编辑或发送 |
| P04  | 发布中 → 发布失败                       | 有可靠证据确认外部未创建内容                       | 保存失败及证据，释放发布锁；不自动再次发送                                     |
| P05  | 发布中 → 发布待核实                     | 超时、断连、回执丢失、进程中断或证据有歧义         | 保留发送记录及锁；不以数据库回滚或无回执推定未发布                             |
| P06  | 待人工发布 → 已发布                     | 用户回填并确认实际内容、账号和批准版本匹配         | 保存链接、确认人和 manual 确认方式；任务终结，不冒充 API 确认                  |
| P07  | 待人工发布 → 发布失败                   | 用户明确确认没有发送，撤销本次人工交接             | 保存未发送声明／证据后释放锁；不提供无条件“退出即可解锁”                       |
| P08  | 待人工发布 → 发布待核实                 | 用户不确定是否已发、回填不匹配，或未完成可核对确认 | 记录差异，保持锁；不得把别的账号／版本回填为批准内容成功                       |
| P09  | 发布待核实 → 已发布                     | 官方查询或人工核实确认成功且匹配                   | 追加核实证据、平台标识和方式；任务置 published                                 |
| P10  | 发布待核实 → 发布失败                   | 有权限人员明确确认未发布                           | 追加核实记录，释放锁；只有后续显式点击重试才可再次发送                         |
| P11  | 发布待核实 → 发布待核实                 | 仍不确定、查询能力不足或内容差异未解决             | 保存新证据并维持锁，不定时自动重发                                             |
| P12  | 发布失败 → 发布中／待人工发布           | 用户明确重试，共同检查再次通过，仍为当前版本       | 同一稳定操作新增 dispatchNo，保留旧发送和核实历史；按渠道进入对应状态          |
| P13  | 待人工发布／发布中／发布待核实 → 原状态 | 重复点击、并发请求、客户端重发                     | 返回当前操作状态，不创建新发送、不释放锁                                       |
| P14  | 已发布 → 已发布                         | 重复成功回执或重复回填同一事实                     | 幂等返回；矛盾证据单独追加并提示，不撤销成功事实或自动补发                     |
| P15  | 已发布 → 原任务不变，新建任务           | 用户选择复制任务                                   | 新 taskId、sourceTaskId；重新生成／编辑、审核、批准；无旧批准或发布记录继承    |

任务当前发布状态优先展示未决实际操作，其次既有成功；否则展示当前版本的最后操作，无操作则未发布。旧版本失败历史继续保留。失败后编辑为新版本时，不得把旧操作重绑新版本。

### 5.2 人工核实与外部故障边界

- 核实记录包含账号、版本、方法、时间、核实人、结论及证据。界面关闭、进程退出和用户等待都不是“未发布”证据。
- 发现实际已发但内容／账号不匹配时，保持待核实并升级人工处理，禁止盲目补发；首期不提供自动删帖、撤回或发布后编辑。
- 对未知请求，只有确认前次不会再生效的可靠结果才能认定未发布；证据不足继续待核实。迟到的成功证据必须关联原发送并阻止新发送，不能覆盖或忽略。
- 模型、搜索和只读工具允许有限技术重试，次数另行配置；发布请求不套用通用自动重试中间件。
- Cloud 上报失败只更新观测故障／补报记录，不回滚业务结果、不改变发布状态、不再发微博。
- 模拟运行不进入上述实际发布成功路径，不解锁真实验收项。

## 6. 复盘状态转换

| 编号 | 当前状态 → 目标状态         | 触发事件与前置条件                                               | 数据变化／限制                                                 |
| ---- | --------------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------- |
| F01  | 未触发 → 处理中             | 用户手动触发；所选尝试已结束，无未决发布或运行工作；有可引用证据 | 创建 Reflection，冻结尝试、版本、审核／发布记录及证据引用      |
| F02  | 处理中 → 已完成             | 输出结构有效，证据与推测明确区分                                 | 保存假设、替代解释、建议及不确定性；不自动创建正式策略         |
| F03  | 处理中 → 失败               | 模型／工具故障、中断或输出无效                                   | 保存错误；不改变原执行或发布结果                               |
| F04  | 失败／已完成 → 新记录处理中 | 用户显式重试／再次复盘；无同任务并行复盘                         | 新建记录并关联旧记录，旧结论不覆盖；按新证据重新冻结输入       |
| F05  | 已完成 → 已完成             | 用户保存某条建议为候选经验                                       | 幂等创建关联候选记忆，保留证据与不确定性；不修改正式策略或权限 |

单次复盘失败不改变发布结果。任务层可以显示最新复盘状态，同时保留历史记录，不能将新的“处理中”写回旧已完成记录。

## 7. 记忆与同步状态

记忆的类型、可用状态和同步状态是三个不同维度；候选处于 active 仍不意味着可用于正式创作。

| 编号 | 当前状态／情形                     | 事件与条件                             | 结果及召回约束                                                                       |
| ---- | ---------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------ |
| M01  | 无候选                             | 用户从复盘保存候选                     | 创建候选及来源；仅复盘／实验可读，正式创作过滤                                       |
| M02  | 候选                               | 明确人工确认，具有权限、依据和适用范围 | 创建已确认经验并保留候选来源和确认信息；不自动改正式策略                             |
| M03  | active → disabled                  | 有权限人员禁用，版本匹配               | 业务库先禁用，立即阻止召回，创建同步任务                                             |
| M04  | disabled → active                  | 人工明确启用，版本匹配且未删除         | 更新版本并同步；仍按类型、用途和确认范围过滤，候选不会因此升级                       |
| M05  | active／disabled → 原可用状态      | 有权限人员编辑，版本匹配               | 创建新版本及同步意图；旧索引版本不能被当作新正文召回，不把一次编辑自动归纳为长期偏好 |
| M06  | active／disabled → deleted         | 人工确认删除，版本匹配                 | 原子写 tombstone、新版本、清理任务及最小审计；立即阻止召回，无回收站和恢复操作       |
| M07  | 同步 pending → running → succeeded | 工作领取并确认目标版本仍有效           | 记录受管副本同步／清理证据；全部范围完成后才标该任务成功                             |
| M08  | 同步 pending／running → failed     | Mem0、索引或其他受管清理失败           | 显示失败、目标范围及原因；业务 deleted／disabled 仍有效，不能继续召回                |
| M09  | 同步 failed → pending              | 有界后台重试或人工重试                 | 复用业务记忆和目标版本，记录重试；旧版本任务取消或幂等忽略，不复活删除内容           |

物理清理完成后可保留不含正文的 tombstone 和审计，用于拒绝迟到同步。既有任务版本、证据快照或外部 Cloud 的留存／清理范围需按 PRD 另定；不宣称删除一条记忆等于清除全系统所有历史。

## 8. 三条关键时序走查脚本

以下是待共同执行的走查脚本，并非已完成记录。

### S1 修改后批准失效（R03、R04、R05、R07；AC-05）

1. 当前版本 V1 已通过审核且获批准 A1，尚未点击发布。
2. 用户保存 V2，携带读取时的任务 revision 和 V1。C02 原子创建 V2、失效 A1、清空审核资格并增加 revision；尚不调用审核。
3. 另一成员仍用旧 revision 保存，触发 C03：无覆盖，保留输入。
4. 用 A1／V1 发布或直接发布尚未审核的 V2，均被拒绝，无外部调用。
5. 用户提交 V2 审核，通过后手动批准 A2，再点击发布；服务端重新校验。
6. 竞争走查：发布占锁先成功，则 V2 保存被拒；V2 保存先成功，则旧批准发布被拒。不能出现两者都成功。

待记录证据：版本／revision、批准失效记录、审核目标、拒绝原因、外部发送次数。

### S2 未知发布不重试（R02、R05、R10、R12；AC-06、AC-07、AC-11）

1. 用户点击发布，持久化稳定操作 P1 和发送 D1 后发出请求。
2. 请求超时或进程在收到回执前中断，P1 进入待核实，保持锁。
3. 重复点击、网络重发、服务重启、Cloud 上报失败都不能生成 D2，编辑和重新执行也被拒绝。
4. 核实为成功则记录平台事实并终结原任务；再创作走复制新任务。
5. 有可靠证据确认未发布，才进入发布失败；用户明确点击重试，重新校验批准后在 P1 下创建 D2。
6. 仍不确定或不匹配时保持待核实；迟到回执按原发送处理，不能触发补发。
7. 人工发布交接重复走查：交接占锁、回填核对、未知维持锁；模拟成功不算实际成功。

待记录证据：稳定操作 ID、发送序号及次数、锁状态、核实人和证据、服务重启前后状态。

### S3 候选不自动启用（R09 及 PRD 记忆治理；AC-09、AC-10、AC-12）

1. 手动复盘生成带证据和不确定性的建议，用户保存候选 M1。
2. 正式创作检索不得返回 M1；复盘或实验用途可以读取并标注候选。
3. 一次人工文案编辑、发布成功或将候选状态设为 active，都不能自动生成长期偏好或正式策略。
4. 只有明确人工确认并记录依据和范围，才创建已确认经验；原候选与确认历史仍可追溯。
5. 删除／禁用有效记忆，故意令索引同步失败：正式检索仍立即过滤，界面显示清理失败，不显示全部删除成功。
6. 重试旧版本同步任务和服务重启，确认不能复活已删除记忆。

待记录证据：候选类型／用途过滤、实际使用的记忆 ID 与版本、人工确认记录、删除状态及同步失败记录。
