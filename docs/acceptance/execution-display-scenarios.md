# D9 第三批：任务详情展示与完整场景验收

## 确认后的范围

沿用现有任务详情页，只补充排队、耗时、预算超限、需人工处理原因，以及失败和尝试历史。保留“停止本次执行”和“终止任务”两种操作及区别说明。取消独立参数页面、前端参数展示及完整 Token/费用用量面板；超时、重试、预算和并发配置继续通过环境变量管理。

执行和发布使用模拟步骤及测试注入的可控适配器，不接入真实模型、搜索或微博 API，不将模拟验收视为官方接口联调完成。

## 页面行为

- 执行进度：排队时说明等待执行器领取。待澄清时提示补充答复；预算不足时展示具体失败原因及人工评估建议，说明人工重试不会重置任务预算。执行中断、重试耗尽、配置或用量异常分别提供处理提示。
- 耗时：首次排队耗时取创建到首次领取的时间，未领取的排队记录随时间更新，排队时取消则截止到取消时间；不把澄清后重新排队误称为首次排队耗时。累计执行耗时取持久化累计值加当前运行段，包含调用和技术重试等待，排除排队和澄清等待。步骤及调用显示各自耗时。页面定时更新仅用于展示，超时判定仍由后端完成。
- 历史：每次人工执行单独展示，保留旧失败原因、原因编号、停止或终止原因。步骤可展开首次调用和技术重试记录，包含时间、耗时、状态及旧错误；重试成功后仍能查看之前的失败。运行时读取最新历史，历史加载失败可显式重试。
- 旧数据：缺少控制策略的历史尝试，累计执行耗时显示“未记录”，不能将迁移时默认的零视为实际历史统计。可选的调用或步骤字段缺失时仍能读取原有记录，不伪造历史。
- 发布待核实：明确说明不能直接取消或重新发送，指向既有发布交接及人工核实入口。已有人工核实、发布防重、锁定和重交接规则继续生效。
- 刷新、新标签页恢复数据库状态；手机布局不横向溢出。不新增模拟发布 HTTP 入口或生产页面按钮。

历史接口的步骤增加可选 `execution` 信息（开始/结束时间、重试次数和下次重试时间），仅使用已有数据库字段，本批没有新增迁移。调用获准开始时清除等待重试时间，避免实际调用期间继续显示“等待技术重试”。

## 验收矩阵

| 场景                           | 验证结果                                                                     | 证据入口                                                      |
| ------------------------------ | ---------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 排队、研究、生成时停止本次执行 | 尝试取消，任务保留；迟到结果不能产出、修改终态或新增发布                     | `scripts/publications.test.mjs` 中 D9 `stop_attempt` 三组用例 |
| 排队、研究、生成时终止任务     | 尝试取消且任务终止；后续调度不能产出或新增发布                               | 同文件 D9 `terminate_task` 三组用例                           |
| 发布前取消及与发送竞争         | 取消先提交则适配器零调用；发送占用先提交则拒绝终止并保留核实边界             | 同文件“取消先于发送占用”“终止与取得发送占用并发”用例          |
| 双执行器及并发上限             | 同一尝试只有一个领取标识和一次执行，实际在途工作不超配置                     | `scripts/tasks.test.mjs` 的双执行器、并发上限及心跳用例       |
| 生成中 SIGKILL 后重启          | 原尝试标中断失败，新尝试由人工创建；既有内容正文与摘要、旧步骤及错误保留     | 同文件“执行进程被强制中断后”用例，使用真实子进程              |
| 发布可能已发出后退出           | 新服务仅转待核实，保留发送占用和发布锁，不重发                               | `scripts/publications.test.mjs` “真实子进程发送后退出”用例    |
| 超时、技术重试、预算           | 三层期限、有限退避、预算跨人工尝试、未知用量保留、迟到结果隔离               | `scripts/tasks.test.mjs` 第二批执行控制用例                   |
| 排队、等待澄清与耗时           | 排队显示动态等待；澄清等待不增加执行时间，恢复同次尝试后继续累计             | `tests/e2e/tasks-real.spec.ts` 的 D9 排队及澄清用例           |
| 三类预算不足及人工重试         | 页面显示调用次数、Token、费用各自错误与处理建议，刷新和重试保留旧历史        | 同文件 D9 `calls` / `tokens` / `cost` 三组用例                |
| 技术重试及旧调用失败           | 等待及预计重试时间可见，调用历史可展开，成功后保留旧错误；历史请求失败可恢复 | 同文件 D9 技术重试用例                                        |
| 中断、待核实、旧数据           | 人工处理提示正确；核实入口可到达，不能直接终止；缺失统计显示“未记录”         | 同文件 D9 中断、旧版统计及已有回填核实用例                    |
| 手机和桌面                     | 布局无横向溢出，预算异常说明在两种宽度可读                                   | 同文件排队和预算用例，输出 `test-results/d9-budget-*.png`     |

## 运行

所有测试只写独立临时测试库、使用普通运行角色，不调用真实付费 API。不得指向业务数据库。

```sh
TASK_TEST_DATABASE_URL='<独立 tasks_test_12位随机十六进制库>' PUBLICATION_TEST_ADMIN_URL='<本机测试实例管理连接>' npm run tasks:test
TASK_E2E_ADMIN_URL='<本机测试实例管理连接>' npm run test:e2e -- tests/e2e/tasks-real.spec.ts
npm run check
```

本批没有新增迁移；若前两批的 `0012` / `0013` 尚未应用，仍须按其升级说明停止旧执行器、备份并迁移后再运行新版本。
