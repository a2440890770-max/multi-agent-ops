# D7：发送前校验与任务终止

本批补齐创建发布、内部模拟发送和人工重试的版本/批准/取消检查，并接通任务终止接口与真实详情页按钮。继续保留人工交接；模拟适配器仅供测试注入，未接入微博官方 API。

## 发送前检查

检查在数据库的团队事务锁与任务行锁内进行。实际调用适配器前重新读取当前任务与内容、批准、账号、配置及审核裁决，不沿用页面预览或先前请求的判断。

- 当前内容版本仍是任务当前版本，并与冻结的版本、正文和 SHA-256 一致；摘要由后端计算。
- 当前批准仍有效，绑定当前任务、账号、内容版本和摘要，并与原操作的批准一致。
- 原审核、主观裁决及当前账号配置仍满足发布条件，批准对应的配置版本没有过期。
- 任务没有终止，也没有当前执行尝试的 `terminate_task` 取消意图；已发布任务不能再发起发送。
- 当前没有冲突工作，账号登记与操作资格仍有效。

`stop_attempt` 仅表示停止一次生成，不等于终止任务。停止后人工保存新版本、审核并批准，仍可进入发布流程。

## 已创建操作的检查失败

先核对当前发送是否已经取得 `task_publication_send_claims` 占用。有占用时按可能已发送处理，不因后来版本或批准变化而删除占用、解除锁或再次调用适配器。

确认当前模拟发送尚未取得占用时，检查失败会在同一事务中将操作与发送记为 `failed`，记录完成时间、不可自动重试的错误、拒绝审计，并解除该操作的任务发布锁：

| 错误码                         | 含义                               |
| ------------------------------ | ---------------------------------- |
| `PUBLICATION_VERSION_CHANGED`  | 版本、正文或摘要变化               |
| `PUBLICATION_APPROVAL_INVALID` | 批准、审核、配置或操作资格不再有效 |
| `PUBLICATION_CANCELLED`        | 任务已终止或有终止意图             |
| `PUBLICATION_TASK_CLOSED`      | 任务已经结束                       |
| `PUBLICATION_ACCOUNT_CHANGED`  | 账号绑定变化                       |

说明明确标注“未发送”。重复原请求只读取原操作，不复活发送、不自动切换到新版本。解锁后由用户处理失效原因；保存新版本需重新审核批准。同版本重试仍遵守原批准与人工未发布确认规则。

## 终止任务

详情页提供“终止任务”，打开后填写原因并明确确认。终止不保存尚未提交的文案。接口：

`POST /api/v1/tasks/:taskId/terminate`

请求体为 `{ expectedRevision, reason }`，使用既有 Session、角色、Origin/CSRF 与 `Idempotency-Key`；仅同团队管理员或运营成员可操作，成功返回 202 和最新任务详情。

- 原子记录 `terminatedBy`、`terminatedAt`、`terminationReason`，置任务为 `terminated`，失效当前批准，阻止编辑、审核、执行、重试和后续发布。
- 当前有排队、运行或待澄清的模拟执行时，记录 `terminate_task` 意图、操作者、原因、停止与完成时间，取消剩余步骤并递增工作代次，隔离旧执行；保留已完成的历史。
- 同操作键或不同键的并发终止、键过期、重建服务都复用原终止事实，不覆盖原因或重复写审计。
- 请求结果不明时，浏览器保留原原因和请求键。刷新先读取任务；尚未查到终止时，可查询或显式重试原请求，不自动 POST。版本冲突会保留输入并要求用户重新核对确认。
- 本期不支持恢复已终止任务，不提供撤回或删除已发布内容。

## 取消与发送并发

终止和发送占用使用同一数据库串行化边界。内部模拟操作尚未取得占用时，终止可将其记为未发送失败并解除锁；发送占用先提交时，终止返回 `423 PUBLICATION_LOCKED`。人工交接已经冻结或处于待核实状态时，也不能直接终止解锁，必须先完成原有回填/核实流程。系统不能把取消等同于撤回已经发出的请求。

## 升级与验收

新增迁移 `0011_d7_publication_preflight_termination.sql`，为任务增加三个终止记录字段、完整性检查及成员外键，扩展执行尝试取消范围。已有数据不被重置；历史上仅有终止状态、没有终止元数据的任务继续可读，不伪造操作者或原因。部署前备份并执行 `npm run db:migrate`。

自动化验证入口：

```sh
PUBLICATION_TEST_ADMIN_URL='<本机测试实例的管理连接>' npm run publications:test
MIGRATION_TEST_ADMIN_URL='<本机测试实例的管理连接>' npm run db:test
TASK_E2E_ADMIN_URL='<本机测试实例的管理连接>' npm run test:e2e -- tests/e2e/tasks-real.spec.ts
npm run check
```

测试在独立临时 PostgreSQL 库使用普通运行角色，不写业务数据。覆盖版本替换、批准失效、配置变化、取消意图、未发送失败的持久化与解锁、发送占用后的保守处理、取消/发送并发、终止并发幂等、活动模拟执行停止、团队权限、事务回滚，以及浏览器确认、刷新恢复、断网、响应丢失和版本冲突。
