# D9 第二批：超时、有限技术重试与任务资源预算

本批沿用第一批的数据库执行权、心跳和迟到结果隔离，补齐执行控制和持久化账本。执行器仍使用明确标记的模拟步骤和测试注入的可控适配器，未接入真实模型、搜索或微博发布 API；模拟调用的 Token/费用为已知零，不能把模拟记录当作真实账单。

## 确认后的规则

- 单次调用默认 120 秒，单步骤 5 分钟，每次完整执行累计 20 分钟。总时长包含运行、步骤间调度和技术重试等待；排队及等待澄清不计入。澄清恢复同一尝试时保留之前的累计时长，人工重试的新尝试有独立的执行计时。
- 每个步骤最多额外技术重试两次，总计最多三次调用；默认退避为 2 秒、4 秒。技术重试复用原尝试和原步骤，不增加或返还自动修改轮次。
- 每任务跨所有尝试累计最多 50 次调用、100000 Token、10 元人民币估算费用。人工重试、服务重启和后续配置变更都不会清零任务预算。
- 发布不进入通用调用/重试层。真实模型及只读适配器必须声明请求用量上界和计价版本，调用应遵守传入的 Token/费用上限；未配置时拒绝发送。适配器内部的每个外部请求都必须经过记账，不能通过隐藏重试或不受控的多轮请求绕过上限。

## 预占、结算与历史

调用前在任务行锁内原子检查预算，新增稳定 callId、步骤内 callNo/retryNo、发送期限与调用类别，并把调用次数及 Token/费用上界记入 `task_execution_budgets`。模型/搜索/只读调用在数据库事务外执行。不同执行器无法重复领取同一步骤的在途调用。

`task_execution_calls` 保存原始预占、最终记账、已知/未知用量标记、计价版本、起止时间、结果及脱敏错误。成功返回可信用量后释放多余预占，Token 和费用可以分别结算；未知字段保留预占。技术失败、超时、取消、进程中断或结果提交不确定时，不把未知用量当作零，也不自动退款。适配器返回负值/非法用量时保留预占并失败；报告超过声明上界的消耗时保留报告值并停止，不能隐瞒已发生的超额。实际严格的费用上限还依赖真实适配器根据已配置单价计算完整请求上界并约束请求，本批只验证该接口及控制逻辑。

费用使用人民币百万分之一元的整数，`10000000` 表示 10 元，避免浮点累计误差。记录的是配置计价下的估算/预占合计，不能称为平台实际扣款。当前不内置实时模型单价或汇率；真实服务接入前必须提供相应的计价配置及版本。`execution-pricing.ts` 提供配置读取、请求上界预占和已知用量估价，使用 BigInt 整数向上取整；调用记录的 pricingRef 同时保存版本及实际输入/输出单价。

调用记录只有 running 可以一次性转为 succeeded/failed/timed_out/interrupted，身份及预占字段不可修改；终态不能删除或改写。任务预算的归属、限制快照及已发生的调用次数不能重置。尝试的执行限制快照及已经累计的执行时长不可回退。迁移为调用和步骤建立复合外键，防止跨任务/尝试关联。

## 超时与重试

每次调用取三种剩余时间的最小值作为期限：单次调用上限、当前步骤剩余时间、当前尝试剩余执行时间。超时会发出 AbortSignal，同时结束当前结果接收，不要求不配合的适配器先返回。迟到结果不能推进步骤、创建文案或退款。

总时长和步骤时长另有数据库扫描，执行器重启后及关闭新任务领取时仍会检查。运行中段用 `active_since` 记录，进入澄清、取消、失败和完成时结算到 `active_elapsed_ms`。失去租约时仍沿用第一批规则：原尝试标中断失败，不自动从任意步骤恢复。

只有显式分类的 RATE_LIMITED、UPSTREAM_UNAVAILABLE、NETWORK_ERROR 以及单次调用超时可以技术重试。普通错误、认证/配置/权限/输入问题、步骤/总执行超时、预算不足和用量异常均不自动重试；不能相信错误对象随意附带的 `retryable` 字段。重试次数、等待到期时间和每次调用原因都持久化。每次重试重新预占预算，剩余步骤/尝试时间不足以等待时直接结束。调用后的结果事务不确定会停止续租等待中断处理，不自动重复调用。

主要原因码：`EXECUTION_CALL_TIMEOUT`、`EXECUTION_STEP_TIMEOUT`、`EXECUTION_ATTEMPT_TIMEOUT`、`EXECUTION_RETRIES_EXHAUSTED`、`EXECUTION_BUDGET_CALLS_EXCEEDED`、`EXECUTION_BUDGET_TOKENS_EXCEEDED`、`EXECUTION_BUDGET_COST_EXCEEDED`、`EXECUTION_PRICING_UNCONFIGURED`、`EXECUTION_USAGE_INVALID`、`EXECUTION_RESERVATION_EXCEEDED`。

## 配置、接口与升级

| 环境变量                        | 默认值   |
| ------------------------------- | -------- |
| TASK_CALL_TIMEOUT_MS            | 120000   |
| TASK_STEP_TIMEOUT_MS            | 300000   |
| TASK_ATTEMPT_TIMEOUT_MS         | 1200000  |
| TASK_TECHNICAL_MAX_RETRIES      | 2        |
| TASK_TECHNICAL_RETRY_BASE_MS    | 2000     |
| TASK_BUDGET_MAX_CALLS           | 50       |
| TASK_BUDGET_MAX_TOKENS          | 100000   |
| TASK_BUDGET_MAX_COST_MICROS_CNY | 10000000 |

模型计价另有三个可选环境变量：`TASK_MODEL_PRICING_VERSION`、`TASK_MODEL_INPUT_MICROS_CNY_PER_MILLION`、`TASK_MODEL_OUTPUT_MICROS_CNY_PER_MILLION`。后二者单位为每百万 Token 的人民币百万分之一元，例如单价 2 元/百万 Token 填 2000000；该数值仅为格式示例。三个变量必须同时配置，缺失时不提供模型计价，模拟执行仍可运行。

启动时校验整数范围及 `调用超时 <= 步骤超时 <= 执行总超时`，不接受无限重试或无界等待。新尝试冻结当前执行限制；任务首次领取时冻结任务预算，后续人工重试沿用原任务预算。既有任务没有重置/提高预算的接口，额度不足时需要人工评估后另建任务。

`GET /api/v1/tasks/:taskId/history` 增加可选的 `calls` 和 `budget`，调用记录按 attemptId 关联，支持分别统计每次尝试；执行尝试增加可选 `control`，含限制快照、已累计执行时长及当前计时段。新增字段兼容旧缓存/预览响应，共享类型与生成响应契约同步更新。[第三批页面与完整场景验收](execution-display-scenarios.md) 展示排队、耗时、预算超限、需人工处理原因以及失败和尝试历史；用户已明确不做参数页面或完整用量面板。

增量迁移 `0013_d9_execution_limits.sql` 创建两张账本表，增加计时、重试字段和历史保护触发器。升级前停止旧版后端/执行器，备份后执行 `npm run db:migrate` 再启动新版；不能混合部署缺少预算控制的旧二进制。迁移不执行任务、不清空旧错误或内容，也不伪造旧调用消耗。旧终态继续只读，尚未执行的旧排队记录首次领取时使用默认控制策略。

## 验证

所有数据库和浏览器测试使用独立临时测试库，运行角色为非超级用户，不调用真实付费 API。测试入口沿用第一批：

```sh
TASK_TEST_DATABASE_URL='<可丢弃的 tasks_test_12位随机十六进制库>' PUBLICATION_TEST_ADMIN_URL='<测试实例管理连接>' npm run tasks:test
MIGRATION_TEST_ADMIN_URL='<测试实例管理连接>' npm run db:test
TASK_E2E_ADMIN_URL='<测试实例管理连接>' npm run test:e2e -- tests/e2e/tasks-real.spec.ts
npm run check
```

覆盖三层超时、忽略迟到结果、排队/澄清排除计时、澄清后累计、有限退避和错误白名单；预算在人工重试及配置变更后保留、失败/超时/取消/中断未知用量不退款、已知/部分已知用量结算、结果写库失败原子回滚；旧调用错误和计价版本不可改写；发布不能进入技术重试中间件。既有发布防重与人工核实测试继续执行。
