# D7：发布操作标识、数据库并发控制与发送防重

本批在 D6 人工交接基础上补齐自动发送的数据库占用边界和模拟验收。模拟适配器仅由自动化测试注入，不提供页面、环境变量或 HTTP 开关，不连接微博，也不计为真实发布验收。官方发布接口仍未接入。

## 防重规则

- 同一 `(taskId, contentVersionId, accountId)` 永久对应一个 `operationId`，人工与其他通道共享此身份。HTTP 请求标识过期、换键、换成员或重建服务，都不能创建第二个发布操作。
- `dispatchId` 标识一次发送尝试。只有人工确认未发布、确认前次发送已停止，且原版本、账号、审核、配置和批准仍有效时，才可显式重试。重试复用操作编号，新增发送编号和递增序号，不覆盖旧历史。
- 创建操作、冻结快照、发送记录、任务发布锁、审计和 HTTP 幂等结果同事务提交。已有任务行锁、团队事务锁和数据库唯一键负责跨请求、跨连接的并发控制。
- 新增数据库唯一索引，使同一个操作最多有一个待人工、发布中或待核实的发送。
- 自动调用前向 `task_publication_send_claims` 插入发送占用，`dispatchId` 是主键。占用与发送前检查、审计同事务提交；只有成功取得占用的调用者可以进入适配器。占用禁止修改或删除，不能靠清除 HTTP 幂等缓存再次发送。
- 适配器接收稳定的操作编号、发送编号、发送幂等键及冻结快照。外部调用在数据库事务外执行，每次发送至多调用一次适配器。

## 未知结果与恢复

模拟发送区分成功、明确失败、未知结果。超时、适配器异常或响应丢失进入待核实，保留发布锁，不自动补发。已经调用适配器后的明确失败也不自动重试，必须补充人工未发布确认。发送占用前的校验失败处理及任务终止见[后续实现](publication-preflight-termination.md)。

发送进程在提交操作后或进入适配器后退出，可能留下发布中记录。测试在确认该进程已经退出后调用内部恢复入口，将记录转为待核实；恢复只更新状态，不调用适配器。结果保存事务失败时同样保留发送占用，恢复后核实，不依据缺少成功回执推断未发送。迟到的旧发送回执不能覆盖已恢复或已人工处理的结果。

上述机制保证系统调用的防重；人工在微博端自行操作仍需要遵守交接与核实流程。

## 迁移

新增 `0010_d7_publication_send_claims.sql`，包含发送占用表、复合外键、不可变触发器、未决发送唯一索引及内部模拟通道约束。旧迁移与业务历史不变；迁移不会创建发送或调用外部服务。业务环境更新代码前备份数据库，再执行 `npm run db:migrate`。

`simulation` 只存在于内部服务输入和结果模型。HTTP 发布及重试请求的通道仍只接受 `manual` / `official_api`；普通服务不注入适配器，官方调用继续返回未实现。

## 自动化验证

使用具有创建临时库和角色权限的本机 PostgreSQL 管理连接：

```sh
PUBLICATION_TEST_ADMIN_URL='<本机测试实例的管理连接>' npm run publications:test
```

测试自动创建并清理 `publication_test_*` 数据库和普通运行角色。未显式设置管理连接时，优先使用 `TASK_TEST_DATABASE_URL`，否则读取本地 `.env` 的 PostgreSQL 管理配置；所选账号必须具有创建测试库和角色的权限。不会迁移或写入业务数据库。

`npm run tasks:test` 同时包含本批发布测试。覆盖：

- 两个独立连接池并发提交同一版本 10 次，只有一个操作、一个发送、一次适配器调用。
- 跨成员、换键、同键不同请求、键过期及连接池/服务重建的防重。
- 适配器超时、响应丢失、未知结果，以及真实子进程发送后退出。
- 待核实不自动发送；继续等待保持锁定；人工确认未发布后，10 次并发重试仅新增一次发送。
- 明确失败仍需人工确认，批准失效或任务取消后禁止发送/重试。
- 数据库直接拒绝重复业务身份、第二个未决发送、修改或删除占用。
- 发送前占用审计失败不调用适配器；发送后结果事务失败不重发。
- 普通服务不启用模拟能力，HTTP 拒绝模拟通道，人工交接保留原有防重行为。
