# D9 第一批：后台执行权、租约与中断识别

执行器随 Fastify 后端启动，默认每个执行器同时持有一个任务，可配置并发上限。继续使用 PostgreSQL 和现有任务接口，无新增队列服务。实际工作仍为明确标记的模拟步骤；可控步骤适配器只用于验证异步调用、取消信号和迟到结果，未接入真实 Agent 或官方发布 API。

## 领取与提交

领取只接受到期的 queued 尝试，且任务开放、当前尝试及工作代次匹配、没有取消意图、发布锁、成功发布或活动审核。任务和尝试在短事务内通过 `FOR UPDATE SKIP LOCKED` 互斥，原子提交领取标识、执行器 ID、运行配置快照、步骤开始与审计。不同执行器不能推进他人的有效租约。

步骤调用在事务外运行；同一尝试在一个进程中最多有一个在途步骤。调用前和结果提交前，重新检查当前尝试、代次、领取标识、执行器、取消意图和租约。失效结果无法创建文案或更新任务。步骤调用失败保存脱敏的 `EXECUTION_STEP_FAILED`，不自动再次调用；调用后结果提交不确定时停止续租，等待中断收敛，不重调原步骤。

执行器用独立心跳续租，即使正在等待慢步骤也会续租。生产领取、续租、失效判断使用数据库时间，续租在数据库真正执行更新时判断是否过期，过期租约不能复活。并发上限按单个执行器计算，多个后端实例的总并发为各自上限之和。

## 中断与历史

第一次后台轮询和后续轮询均检查过期执行，不依赖浏览器访问。有效租约不会因其他后端启动而失效。失效的 running 尝试标为 failed，运行步骤保存 `EXECUTION_INTERRUPTED`，剩余步骤取消，工作代次递增后释放工作槽；已有取消意图的遗留执行收敛为 cancelled。过期尝试不会重新放入队列。queued 记录仍可被正常领取，待澄清记录继续等待答复。

强杀后最迟在原租约到期并被轮询到时收敛；优雅关闭主动隔离未完成执行。已经结束的步骤、旧文案、输入配置和失败原因均保留。人工重试沿用原接口，新增 attemptId/attemptNo，从头开始。澄清后仍为同一尝试，但领取新的执行权，保留已完成步骤和首次开始时间。

## 发布保护

发送占用记录保持不可变，并新增发送期限：晚于适配器自身超时 30 秒。后台扫描在期限到达后把未决发送改为 `verification_required`，保留原操作、发送占用及发布锁，不调用适配器。迟到回执不能覆盖已收敛的状态。

没有取得发送占用、且超过领取等待期限的发布操作，可确定未发送，保存 `PUBLICATION_NOT_SENT` 并解锁。旧占用没有期限时，保守等待原占用时间加 330 秒（旧模拟适配器最大超时 300 秒加余量），再进入待核实。人工交接不套用自动中断扫描。即使 `TASK_EXECUTOR_MODE=disabled`，后台仍检查遗留执行与发布，但不领取新任务。

## 配置及升级

| 环境变量                   | 默认值 | 约束                                        |
| -------------------------- | ------ | ------------------------------------------- |
| TASK_EXECUTOR_CONCURRENCY  | 1      | 1–32；每执行器上限                          |
| TASK_EXECUTOR_POLL_MS      | 500    | 10–60000 毫秒                               |
| TASK_EXECUTOR_HEARTBEAT_MS | 5000   | 10–60000 毫秒                               |
| TASK_EXECUTOR_LEASE_MS     | 30000  | 100–600000 毫秒，至少为心跳和轮询间隔的三倍 |

运行参数保存在尝试的 `runtime_policy` 中；领取/中断事件写入审计，心跳不增加任务 revision。现有请求、共享响应与前端接口保持兼容。配置非法时后端拒绝启动。

新增迁移 `0012_d9_execution_ownership.sql`，不修改已应用的旧迁移，不清空或重置业务记录。升级前停止所有旧版后端/执行器，备份后执行 `npm run db:migrate`，再启动新版本；旧二进制没有租约校验，不支持与新版混合运行。迁移本身只增加字段、索引和完整性约束；旧 running 记录由新版后台识别为中断，旧 queued 记录继续排队，历史终态保持原样。无需为增加并发更换框架或增加服务。

## 验收

在独立 PostgreSQL 测试实例运行，禁止指向业务库。`TASK_TEST_DATABASE_URL` 必须指向可丢弃的 `tasks_test_<12位随机十六进制>` 数据库；其他管理连接用于创建随机临时库并自动清理。

```sh
TASK_TEST_DATABASE_URL='<独立测试库连接>' PUBLICATION_TEST_ADMIN_URL='<测试实例管理连接>' npm run tasks:test
MIGRATION_TEST_ADMIN_URL='<测试实例管理连接>' npm run db:test
TASK_E2E_ADMIN_URL='<测试实例管理连接>' npm run test:e2e -- tests/e2e/tasks-real.spec.ts
npm run check
```

- A1/A2：两个执行器并发领取同一尝试，仅一次领取/开始；并发配置为 1/2 时，数据库领取和实际在途步骤均不超上限；慢步骤不持有任务行锁。
- A3：有效心跳租约不被另一个执行器误判；过期后不能续租、推进或写入结果；旧步骤在人工新建尝试后迟到，不影响新尝试。
- A4：真实子进程在生成阶段被 SIGKILL，另一个进程将原尝试标失败，人工重试新增尝试；慢调用期间心跳独立工作；不确定结果事务不触发自动重复调用。
- A5：真实发送子进程退出后，后台扫描在期限到达时转待核实，重复扫描不重复审计、不重发，发布锁保持有效。
- A6/A7：旧错误/步骤及历史查询保留；审计失败回滚领取；增量迁移保留原运行记录和配置；非法租约或并发参数拒绝启动。

步骤/任务超时、有限技术重试和累计资源预算见 [D9 第二批](execution-limits.md)。真实 Agent 接入仍属于后续范围，不将模拟成功计为真实业务执行验收。
