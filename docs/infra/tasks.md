# 任务创建与详情查询接口

沿用现有契约 `POST /api/v1/tasks`，admin 和 operator 均可创建。需要有效的 `ops_session` Cookie、可信 `Origin`、会话绑定的 `X-CSRF-Token` 和 16—128 字符 `Idempotency-Key`。先应用增量迁移：`npm run db:migrate`。

```json
{
  "title": "产品功能介绍",
  "originalRequest": "面向新用户介绍三个核心功能，保留实际证据。",
  "referenceInputs": [{ "label": "产品说明", "url": "https://example.com/product" }]
}
```

`title` 和 `originalRequest` 必填，分别不超过 120、10000 字符且不能仅为空白。`referenceInputs` 可省略；名称不能仅为空白，地址按已有 URI 契约校验。原始文字、空格和换行按原样保存。参考资料 ID 由服务端生成，创建人和团队取自当前登录身份。客户端不得指定归属、账号、生命周期、执行状态或版本。

团队已配置 `accounts` 中的唯一固定账号时，服务端自动绑定；尚未配置时同样允许创建，返回 `task.accountId=null`、`account=null`，数据库 `account_id` 保存为空。其他团队账号不可借用，也不自动创建占位账号。管理员初始化不会创建平台账号。创建草稿不要求平台授权已有效，也不创建授权或调用平台。

后续配置团队账号不会自动回填已有草稿，原创建请求的幂等重放也保留原始未绑定结果；新创建的任务可以自动绑定已经配置的账号。已有草稿需要通过后续的绑定流程关联账号，账号相关执行和发布前必须完成绑定。账号配置和任务绑定接口尚未实现。

成功返回 `201 { data: TaskDetail, meta: { requestId, replayed } }`。初始任务 `lifecycle=open`、`revision=1`；执行状态、当前尝试、当前步骤、内容、审核、批准和发布引用均为空。创建只保存草稿，不执行模型、搜索、澄清或发布。`actions.start` 根据状态及执行器配置返回是否可启动模拟执行，其余操作按真实可用性返回。

同一动作重传必须复用同一键。作用域按团队、操作者、方法和规范化路径隔离，JSON 对象键顺序不影响指纹，省略参考资料与空数组等价。同键同请求在至少 24 小时内返回原任务与原参考资料 ID，并设置 `meta.replayed=true`；同键不同请求返回 `409 IDEMPOTENCY_KEY_REUSED`。新键表示新的创建意图，可以创建相同文字的另一项任务。重放仍校验会话、权限和原任务归属。

任务、重放记录和 `task.created` 审计在同一数据库事务提交，跨进程事务锁保证并发重复请求只创建一条。数据库或审计失败返回安全的 `503 DEPENDENCY_UNAVAILABLE`，整笔回滚；网络中断后使用原键重试。原始要求和数据库错误不写入请求日志。

## 任务详情查询

`GET /api/v1/tasks/:taskId` 需要有效 Session；不要求 `Origin`、`X-CSRF-Token` 或 `Idempotency-Key`。同团队 admin 和 operator 可以查看他人创建的任务。

成功返回 `200 { data: TaskDetail, meta: { requestId, replayed: false } }`。单次 SQL 从当前数据库一致读取任务、查看者成员身份及绑定账号摘要，返回标题、原始要求、参考资料、原创建人、所属团队、生命周期、版本、创建/更新时间、执行状态、`currentStep` 和 `errorMessage`。任务尚无执行时这些执行字段为空；旧原型状态 `needs_human` 按共享契约投影为 `manual_required`。`errorMessage` 是新增的详情字段，创建结果也提供该字段（初始为空），兼容已有创建重放记录。

任务未绑定账号时 `task.accountId`、`account` 均为空，不会因团队后来配置账号而隐式绑定。已绑定账号仅返回 ID、名称、平台、授权状态和官方发布能力，不返回凭据引用或令牌。

不存在、跨团队或不能对应数据库 UUID 的标识统一返回 `404 NOT_FOUND`；未登录先返回 `401`。旧数据缺少团队归属时不自动分配给当前团队；同团队历史任务缺少创建人，或误绑其他团队账号时返回 `409 INVALID_STATE`，需要管理员核对原始归属。查询不修复数据、不写业务审计或幂等记录、不修改任务或会话，响应禁止缓存。数据库异常返回脱敏的 `503 DEPENDENCY_UNAVAILABLE`。

已接入执行尝试、模拟产出与基于当前尝试/工作代次的工作槽，详情返回当前记录。真实审核、批准和发布尚未实现，相应当前对象为空且操作不可用。任务列表查询已实现，详见下文。执行功能新增 `0003_d4_execution_attempts.sql` 迁移。

## 前端创建与详情闭环

`/tasks/new` 已接通真实创建接口，提交标题、原始要求及可选参考资料（名称缺省为“参考资料”）。输入保留原始空格和换行；空白标题/要求、缺少链接的参考资料名称和非 HTTP/HTTPS 链接在提交前提示。请求携带当前会话 CSRF 和新生成的动作键，提交中禁用表单，重复触发提交由同步锁拦截。

创建返回有效的 201 后跳转 `/tasks/:taskId`，详情页重新 GET 当前数据库状态；刷新、重新打开链接或新标签页访问均恢复登录身份后再查询。详情展示原始要求、参考资料、创建人和团队 ID、状态、当前步骤、错误及账号摘要。未绑定账号显示“未绑定”。支持加载、404、403、409、服务错误及手动重试；身份切换后重新校验访问，不继续展示旧团队数据。参考资料仅将 HTTP/HTTPS 地址渲染为外部链接，原始要求按文本显示。

网络失败、超时或异常创建响应不会被当作创建成功，也不自动发起第二次创建。当前标签页用 Session Storage 暂存当前团队/成员的输入和未确认请求，不保存密码、Cookie 或 CSRF。未确认时冻结输入，手动“重试确认本次提交”复用原动作键及原请求，即使刷新也不更换；明确未接受的校验/认证失败可修改输入或重新登录后继续。成功确认后清除本地草稿。超过 23 小时的未确认提交先核实结果，避免跨过服务端 24 小时重放期限后盲目创建。浏览器禁用存储时仍支持本次页面内提交和重试。

真实任务路径不回退示例数据。原示例详情保留在明确的 `/previews/tasks/:taskId` 路径，真实列表链接到 `/tasks/:taskId`；列表的“创建任务”进入真实表单。真实列表、创建和详情页不显示“操作不会保存”的预览提示。详情可启动、停止或重新进行模拟执行并查看历史；账号绑定、真实 Agent、审核和发布尚未接入。

## 验证

设置独立的 `TASK_TEST_DATABASE_URL`，指向可丢弃的 `tasks_test_<12位随机十六进制>` 数据库，然后运行：

```sh
npm run tasks:test
```

测试不读取项目 `.env`，会清空临时库测试数据。覆盖创建和详情契约、持久化、原文保留、权限、团队隔离、并发幂等、服务重建重放、非法输入、无账号创建/查询、账号配置后原请求重放、事务回滚和故障脱敏。详情查询还验证当前状态更新、只读数据库连接、旧数据缺失归属、账号错绑和历史状态兼容。实际接口使用普通运行角色。CI 的 `task creation` 作业运行同一测试。

前端错误、权限、提交与重试行为及手机布局由以下浏览器测试验证：

```sh
npm run test:e2e -- tests/e2e/tasks.spec.ts
```

真实持久化闭环使用独立临时 PostgreSQL 库和真实 Session/任务服务。显式设置本机 `TASK_E2E_ADMIN_URL`（具有创建测试库和角色权限的管理连接）后运行：

```sh
npm run test:e2e -- tests/e2e/tasks-real.spec.ts
```

该测试只创建随机命名的 `tasks_ui_test_*` 临时数据库和普通运行角色，结束后清理，不向业务库写验收任务。验证浏览器创建后的数据库记录、刷新与新标签页恢复、账号为空，以及“数据库已提交但 HTTP 响应丢失”后重试仍只创建一条任务和成功审计。未提供测试管理连接时显式跳过，CI 的任务作业提供隔离实例并执行。

## 任务列表与状态筛选

`GET /api/v1/tasks` 从数据库只读查询当前团队的任务，同团队成员可查看彼此创建的历史。支持标题或任务 UUID 的字面子串搜索 `q`（`%`、`_` 不作通配符），以及 lifecycle、execution、approval、publication 的 AND 组合筛选。执行状态 `needs_human` 映射为 `manual_required`。审批与发布尚未接入，因此当前记录分别为 `not_requested` 和 `not_published`，其他相应筛选返回空列表。

默认每页 20 条，limit 范围 1–100；按 updated_at DESC、id DESC 分页，游标保留数据库时间的微秒精度并绑定团队与筛选条件，条件变化后应重新从第一页查询。返回 `Page<TaskSummary>`，不返回账号凭证，不写审计或业务状态。缺少创建人或账号团队归属异常时返回 409，供管理员核对，不伪造归属信息。

`/tasks` 展示真实数据、加载/失败/重试/空结果以及“加载更多”。搜索和状态切换重新查询，详情返回列表和刷新页面都会重新读取数据库。页面不再展示固定示例任务或固定数量统计。无需新增迁移。

## 执行尝试记录与模拟执行器

应用 `0003_d4_execution_attempts.sql`：新增 execution_attempts、execution_steps、task_contents，tasks 增加当前尝试/产出引用及 work_generation；audit_events 增加 task_id 并为历史任务审计建立关联。复合外键保证当前尝试和产出属于原任务；唯一索引防止同任务同时存在多个活动尝试。迁移不改变已有任务的原始要求、归属或执行状态。

- `POST /api/v1/tasks/:taskId/attempts`：首次启动，提交 expectedRevision；可选 simulationScenario 为 success（默认）、failure、clarification。
- `POST /api/v1/tasks/:taskId/attempt-retries`：提交 expectedRevision、previousAttemptId、restartTerminated=false、reason，及可选 simulationScenario；只允许当前尝试已结束、任务 open 时从头新建尝试，旧尝试及步骤保持不变。重启已终止任务尚未实现。
- `POST /api/v1/tasks/:taskId/attempts/:attemptId/stop`：提交 expectedRevision、reason。模拟器没有外部调用，因此同一事务即可取消未完成步骤、隔离旧工作代次并确认停止，保留停止人、原因和时间。
- `GET /api/v1/tasks/:taskId/history`：同团队只读查询，返回所有尝试及步骤（每任务最多 100 次尝试）；audit 支持 limit/cursor 分页，游标只用于当前团队及任务。

写入需要 Session、Origin/CSRF 和 Idempotency-Key。任务行锁串行化启动/停止/重试，比较 expectedRevision；同键同请求 24 小时内重放原 202，不再次调度；同键不同请求 409。尝试、步骤、任务投影、幂等记录和审计同事务提交。数据库或审计失败整笔回滚，使用原动作键重试确认。

输入原文、参考资料、输入 revision、模拟模式、情形、模拟器 v1 及步进间隔保存在每次尝试的冻结快照中。当前 configVersion=1 指模拟器配置版本，不冒充团队账号配置；快照及凭据不返回浏览器。模拟执行无需绑定微博账号。

后端 MockTaskExecutor 轮询数据库中的到期检查点，通过任务行锁 SKIP LOCKED 以及当前尝试/工作代次匹配推进，每一步与状态、审计一同提交。后端或工作进程重启后继续处理已提交的 queued/running 记录；多个进程不会重复推进同一检查点。查询接口不会推进执行，前端只轮询读取进度。优雅关闭等待当前事务结束；数据库暂不可用时保留检查点并稍后重试。

正常流程依次模拟检查要求、研究、生成和检查产出，最终 ready 并保存明确标记为模拟的内容。失败情形在研究步骤保存 MOCK_RESEARCH_FAILED，任务和步骤展示错误且可重试。澄清情形在检查要求后保存关联当前尝试的问题、进入 awaiting_clarification，并清除调度时间；不会进入后续生成步骤。待澄清状态支持提交答复；只答部分问题时继续等待，全部问题均有非空答复后恢复同一次尝试。需要退出等待时可停止尝试。

本地默认 `TASK_EXECUTOR_MODE=mock`；设为 disabled 时禁止新启动/重试，历史查询和停止已有模拟执行仍可用。生产默认 disabled，显式 mock 也会拒绝启动。模拟器不调用真实模型、搜索、微博发布或外部服务；模拟产出不生成审核通过、批准或发布资格。Agent 服务的 canExecuteTasks 仍为 false，当前执行器位于业务后端。

详情中的“模拟执行”区支持情形选择、启动、停止和重新执行；“执行尝试记录”区展示次数、发起人、状态、开始/结束时间、步骤耗时与错误。运行中自动读取最新详情及历史，刷新仍从数据库恢复。提交期间防重复点击；网络结果不确定时，当前团队/成员/任务的操作标识和原命令保存在 Session Storage，刷新后手动重试仍复用原键，不保存 CSRF、Cookie 或密码。

验证：`npm run tasks:test` 覆盖真实 PostgreSQL 状态流、并发幂等、旧代次隔离、停止、从头重试、工作进程重建、审计失败回滚及团队权限。真实浏览器测试同时验证创建、执行、刷新、模拟产出、失败重试、澄清阻断和响应丢失后的操作确认；所有验收数据均在独立临时数据库中创建。

## 澄清答复与继续执行

`0004_d4_clarification_answers.sql` 新增 clarification_answers 表，保存 task_id、attempt_id、question_id、问题快照、原文答复、答复成员及时间。复合外键保证原任务与尝试一致，唯一约束保证同尝试同问题只保存一次。当前已保存的答复只读，不覆盖历史；重新执行的新尝试有独立问题与答复，历史仍可查询。

`POST /api/v1/tasks/:taskId/clarifications` 已实现。请求含 expectedRevision、attemptId、answers[{questionId,answer}]；需要 Session、Origin/CSRF 与 Idempotency-Key，成功返回 202 TaskDetail。服务器核对当前任务/团队/尝试/工作代次、待澄清状态及问题归属；拒绝空白或超长答复、重复问题编号、已回答问题、旧尝试、停止后答复及客户端伪造答复人。答复、问题投影、状态、审计及幂等重放记录同事务保存，失败整笔回滚。同键重复提交只确认原结果，原有启动/停止/重试操作的动作键指纹保持兼容。

允许只答当前未答问题中的一部分，此时保持 awaiting_clarification、无调度时间、无生成；全部问题均有非空答复后进入 queued，恢复同一 attemptId 和 attemptNo，从尚未完成的步骤继续，首次开始时间与已完成步骤不变。原始要求和冻结配置不改写，模拟产出单独附上澄清问题与答复。模型、搜索、审核和发布仍不调用。

详情页的“澄清问答”区可填写和提交，未提交草稿按团队/成员/任务/尝试暂存在当前标签页，刷新可恢复。明确失败保留输入，网络结果不确定时冻结输入，手动重试复用原键及原请求。已保存答复随详情刷新恢复；执行历史返回 clarificationAnswers，可看到原尝试、问题、答复人和时间，即使重新执行后仍保留旧答复。

当前沿用模拟情形生成问题，只校验答复是否非空及所有问题是否已回答；不判断自然语言是否充分，也不自动识别主题缺失和语义冲突。显式结构缺失、可枚举矛盾可后续通过规则检查，复杂语义分析可接 AI 或人工判断，本次不引入真实 AI。
