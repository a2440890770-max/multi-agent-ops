# D3 服务端 Session 认证

已实现三个接口，前缀为 `/api/v1`，前端 `/login` 已接通真实登录、身份恢复和退出。业务接口已统一接入服务端会话、角色及写入 Origin/CSRF 校验；通过权限检查后，成员管理、配置和其他业务处理仍为 501 占位。

| 方法与路径          | 输入与行为                                                                                                          |
| ------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/login`  | JSON `{ login, password }`；可信 `Origin` 和 16—128 字符 `Idempotency-Key`；返回 Session，设置 `ops_session` Cookie |
| `GET /auth/me`      | 使用 Cookie，返回当前成员、权限、会话绑定 CSRF Token 和绝对过期时间                                                 |
| `POST /auth/logout` | 可信 `Origin`；有效会话还需 `X-CSRF-Token`；撤销当前会话、清 Cookie，重复或过期退出成功                             |

Session 响应使用现有 `{ data: { member, permissions, csrfToken, expiresAt }, meta: { requestId, replayed } }`。失败使用共享 ApiError：字段/格式错误 400；凭据错误或会话失效 401；来源或 CSRF 不满足 403；动作键冲突 409；限流 429；依赖不可用 503。所有认证响应均 `Cache-Control: no-store`。错误提示不区分未知、禁用账号与错误密码，不输出驱动堆栈或 SQL 参数。

## 运行配置

业务连接沿用根目录 `.env` 的 `DATABASE_URL`，必须先完成业务表迁移并初始化成员。新增：

- `AUTH_SECRET`：32 字节随机值的 64 位十六进制编码。用于密钥分离后的登录请求 HMAC、限流标识和 AES-256-GCM 重放加密；不提交 Git、不输出到日志。重启必须保持相同值才能重放原登录请求。它不替代会话随机凭证。
- `AUTH_TRUSTED_ORIGINS`：逗号分隔的精确 Origin。开发默认接受 localhost 和 127.0.0.1 的 5173/3001 端口；其他来源须显式指定。禁止通配符、路径和内嵌凭据。
- 生产必须设置 `NODE_ENV=production`、随机 `AUTH_SECRET` 和 HTTPS `AUTH_TRUSTED_ORIGINS`，使用同源 HTTPS。生产 Cookie 为 `HttpOnly; Secure; SameSite=Lax; Path=/`；开发仅允许本机 HTTP。

未配置认证密钥时，健康接口仍可启动；登录返回 503，不创建模拟会话。数据库中已有启用的管理员也不能替代认证密钥。若本地登录页提示“登录服务暂不可用”，先在项目根目录运行 `npm run env:setup`，它会补齐缺失或空的本地 `AUTH_SECRET`，不会覆盖已有密钥或数据库配置；然后重启 `npm run dev`，重新登录。

部署密钥请通过秘密配置注入；生产环境不会自动生成密钥。也可在本机生成并安全保存：

```sh
node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('hex'))"
```

该命令的输出是秘密，不应贴到公开日志或提交仓库。

## 会话、重放与限流

- 使用 32 字节随机不透明 Cookie，数据库仅保存 SHA-256 摘要。登录起绝对有效 8 小时，读取不续期。CSRF Token 使用每会话随机材料派生并保持稳定。
- `/auth/me` 每次读取当前角色、成员状态、认证版本及密码修改时间。角色改变立即体现在响应；禁用、认证版本变化或改密后旧会话被拒绝。后续改密/禁用接口仍须在事务中递增认证版本并撤销相应会话。
- 相同账号/Origin、动作键和请求重传复用同一会话，返回 `replayed=true`。权限返回当前角色。会话已退出或过期时不恢复，使用新动作键重新登录。登录凭据仍须有效。动作键指纹包含原始登录字段；账号匹配时忽略两端空白和大小写。
- 登录记录默认保留至少 24 小时；仅在处理相同过期键时清理该记录，定期清理任务后续按数据保留政策配置。Cookie 重放材料只存 AES-256-GCM 密文，数据库中不保存可重放的明文凭证或原始密码；请求指纹采用服务端 HMAC。
- 会话、成功审计和重放记录同事务提交；相同请求使用事务级锁防止并发重复创建。失败不会产生已成功会话。
- 使用业务库安全审计中的 `auth.login_attempt` 持久记录和事务级锁限流，默认每账号 15 分钟 5 次、每 IP 15 分钟 30 次。记录包含 HMAC 标识，不保存原始账号/IP。限流对不同进程及重启生效，返回 `Retry-After: 900`。Origin、请求结构校验在登记尝试之前执行；成功、失败及重传都消耗额度。健康检查、`/auth/me` 不消耗登录额度。

## 业务接口权限

业务路由按 `shared/src/contracts.ts` 的 `roles` 统一授权，不能通过请求头、查询参数或正文指定当前身份：

| 请求身份或条件                                             | 返回结果                                                     |
| ---------------------------------------------------------- | ------------------------------------------------------------ |
| 未登录、伪造/过期/撤销会话、成员禁用或认证版本失效         | `401 UNAUTHENTICATED`                                        |
| 运营访问成员列表/修改成员、账号官方授权入口、配置读取/修改 | `403 FORBIDDEN`                                              |
| 业务写入缺少可信 Origin 或有效的会话绑定 CSRF              | `403 FORBIDDEN`                                              |
| 管理员访问管理接口，或管理员/运营访问普通业务接口          | 通过权限检查；结构合法后仍返回业务占位 `501 NOT_IMPLEMENTED` |
| 持有 Cookie，但认证配置或数据库不可用                      | `503 DEPENDENCY_UNAVAILABLE`；不会放行                       |

`backend/src/authorization.ts` 在独立业务路由作用域的 `onRequest` 阶段执行检查，先于 JSON 解析、动作键及参数校验；响应使用统一 ApiError 和 `Cache-Control: no-store`。每次请求通过现有会话读取最新成员角色、状态、认证版本及改密时间，不使用客户端角色或旧的角色缓存。角色改变对下一次请求生效；已进入业务处理中的请求没有追溯取消机制。

后续业务路由须注册在这一受保护作用域中，并声明 `config.requiredRoles`；未声明时默认拒绝。通过检查后，处理器从 `request.authSession` 读取可信的成员及团队上下文。各业务对象的同团队查询、跨团队 404、资源状态机及事务内权限复核须随对应业务处理实现，本次没有以角色检查代替对象归属检查。健康检查、公开 OpenAPI 及登录/退出的现有专门规则保持独立。

## 前端登录

前端使用同源 Cookie，密码不写入 localStorage/sessionStorage，CSRF 仅保存在内存。业务页面先检查 /auth/me，未登录跳转登录页并记录受限的站内返回地址；登录成功后再次查询当前身份，再返回原页面。侧栏角色来自服务端，不提供预览身份切换。概览 / 保留公共服务状态检查。

会话按服务端绝对到期时间退出本地身份；刷新、恢复可见和已登录时每 30 秒重新查询当前身份。不同标签页通过不含凭据的 BroadcastChannel 消息同步。退出须等待服务端确认，失败保留身份并提示；未知登录结果只重新检查会话，不自动重放写入。后台身份检查不会覆盖正在执行的登录或退出。

`npm run test:e2e` 覆盖登录表单、角色布局、导航、刷新恢复、退出、错误、过期、返回地址和移动端。认证页面回归使用浏览器级模拟响应，不向实际管理员账号反复提交密码；真实后端的数据库集成测试使用下述独立测试命令。任务、成员和配置页面仍明确标注示例数据及未接通操作。

## 验证

`npm run check` 包含配置、Cookie 解析和未配置时的认证测试。独立 PostgreSQL 集成测试使用：

```sh
npm run auth:test
```

运行前显式设置 `AUTH_TEST_DATABASE_URL`，库名必须是 `auth_test_<12位随机十六进制>`。测试不读取项目 `.env`，会清空该临时库的测试表；需要临时库初始化角色来建表和创建普通测试角色，实际接口通过非超级用户测试。覆盖会话持久化、过期、退出、CSRF、当前角色、禁用和改密失效、并发重传、跨实例限流、事务回滚、日志脱敏及依赖失败；另遍历全部业务契约验证管理员、运营、未登录三种身份，覆盖越权、身份伪造、鉴权顺序、角色变更及默认拒绝。CI 的 authentication 作业在独立临时 PostgreSQL 中运行同一测试。不可使用业务库或记忆库。
