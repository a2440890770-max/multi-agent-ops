# GitHub 项目研究

本 Skill 的分析方法与六个必需章节已由用户于 2026-11-08 确认。由宿主预加载完整内容，仅用于 Research；不依赖 SDK 自动发现 Skill。

## 使用上下文

以宿主提供的 `ResearchContext` 为研究边界：只研究 `selectedProject`，回答 Supervisor 给出的 `request.questions`，按 `contentContext` 中的受众、目的及禁止事项控制深度。项目不限于 AI；不自行假设读者是开发者、初学者或投资者。

本 Skill 规定分析方法，不授予工具、站点、文件或执行权限。沿用运行时的授权、资源限制、来源登记和输出 Schema；不运行仓库代码、安装依赖或发起试用来补齐结论。不生成最终标题、逐页文案、成品图片、批准记录或发布操作。

## 从研究问题组织取证

先用已有材料把每个 Supervisor 问题映射到下列章节，区分已有依据与需要补查的内容。保留原问题 ID 和核心性；研究中发现会改变主要介绍结论的问题时可以追加，说明影响，不降级原有核心问题。章节必需不表示其中所有未知项都是核心缺口。

优先读取当前仓库中与问题相关的 README、文档、发布说明等一手资料。版本、性能、部署及许可证等结论应绑定实际取得材料的适用范围和时间；不能把仓库描述自动当成当前版本的完整能力。其他官网或文档地址只有经后端配置或真实用户确认后才可读取，README 外链本身不授予访问权限。

每轮按已确认规则尝试搜索 B 站、小红书、抖音，以项目名、仓库标识和研究问题消除同名误匹配。引用第三方观点时保留作者与归属；搜索摘要、标题、排名及 `sdk_processed` 仅作线索。无结果、无法读取或仅有介绍页时如实记录，不推测正文或视频内容，不将这些情况自动设为核心缺口。

视频处理交给实际已加载的 `video-content-extraction`，由它编排受控媒体工具。缺 Skill 或平台不支持时保留限制；不得自行用工具拼接替代缺失 Skill。字幕、转写和抽样画面分别说明分析范围，抽帧成功不代表已完成视觉理解。

## 必需章节

下列六项作为宿主的 `runtimeContext.skills[].requiredSections`。第一列是稳定 requirement ID，对应报告章节的 `requirementRef`；章节自身的 `id` 另行生成。

| requirement ID        | 章节标题           | 研究重点                                                                                                                           |
| --------------------- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| `gpr-overview`        | 项目概述           | 项目是什么，解决什么问题，提供什么形态的产品或工具。区分当前能力与路线图、概念或计划。                                             |
| `gpr-capabilities`    | 核心功能与工作方式 | 主要能力及典型输入、处理、输出；按受众需要解释工作方式，区分内置能力、可选集成和外部依赖。避免照抄全部功能清单。                   |
| `gpr-use-cases`       | 适用场景与人群     | 哪类人在什么情境下可能受益，成立条件是什么；资料未直接验证的应用设想标为推断，不能虚构用户案例或使用成效。                         |
| `gpr-differentiation` | 特点与创新判断     | 提炼有依据的特点；比较或创新判断必须有明确对象、比较维度、证据和适用范围。无比较证据时只描述特点。                                 |
| `gpr-prerequisites`   | 使用门槛与前提     | 选择影响理解或采用的安装/部署方式、运行环境、硬件、账号或外部服务依赖等。按项目适用性取舍，不把所有项目都当成可本地运行的软件。    |
| `gpr-limitations`     | 局限与风险         | 有依据的能力边界、成熟度限制、兼容性及许可证/成本/数据处理等使用注意事项。只研究与本轮目标有关的风险，不生成无来源的通用风险清单。 |

表中研究重点用于指导取证，不要求为每个项目填满所有示例信息，也不预设所有项目有创新、特定硬件门槛或特定风险。

每个必需章节恰好出现一次，遵循当前 Schema 的状态约束：

- `supported`：引用有效 `claimIds`，`gapIds` 为空。
- `insufficient_evidence`：保留章节，引用对应 `gapIds`，`claimIds` 为空。已取得的有效结论仍保留在报告的 `claims` 及问题覆盖中，不因该章节存在缺口而删除。

没有比较证据并不必然使“特点与创新判断”章节证据不足：若已有依据足以描述特点，可保留这些结论及“未形成创新比较结论”的限制。但当 Supervisor 明确要求核实创新或优势时，必须保留该问题及缺口，不能用一般特点代替回答。

“局限与风险”须有实际依据；没有查到问题不等于没有风险。没有找到许可证不等于确认禁止使用，存在开源许可证也不等于图片、标志或第三方素材可以转载。关键采用条件无法确认时明确缺口，不代用户作许可或成本承诺。

## 形成可核查的结论

把足以影响介绍准确性的说法拆成独立 claim，使用现有三种类型：

- `fact`：可核查事实。核心事实需要直接支持该说法的一手依据，或真实确认的一手用户材料；用户材料保留“用户提供，未经外部独立核验”标注。
- `third_party_opinion`：第三方评价或判断，保留归属，不改写成项目已证实的能力。
- `inference`：根据已登记事实或证据形成的分析，引用前提和适用限制，不冒充来源原话或实测结果。

作者的性能或优越性宣称不能自动变成已经证实的性能或比较结论。若证据只证明作者作出过该宣称，限定事实的表述范围；未经实际测试不得写“实测证明”。同一原文的多处转载不当成多份独立证据，来源冲突也不能靠数量投票消除。

保持 `question → claim → evidence → material → source` 可追溯。证据只引用宿主真实登记的材料和 ID；文字摘录匹配已保存文本的 UTF-16 区间，字幕/转写及帧引用匹配真实视频时间位置。不自行生成来源性质、材料内容、用户确认或工具调用记录，不把未经读取的链接写成已核验证据。

## 介绍角度与交接

在现有 `suggestedAngles` 中提供有依据的介绍角度，引用对应 `claimIds` 并保留限制。例如，可围绕有证据的具体使用问题或工作方式提出角度；不把角度写成最终标题、流量承诺或页稿。没有足够依据时允许空数组，不用夸张表达填满。

报告 `summary` 概括项目定位、主要可用结论及关键限制，不能只摘录 README 宣传语。问题覆盖、来源、证据、缺口、冲突与警告使用 Schema 已有字段，不另造一套报告格式。

遇到缺口时说明缺什么、影响哪个问题或章节、需要什么补充材料。没有第三方讲解、可选视频处理失败与核心事实缺证分别判断；前两项不必然阻断，核心缺口不得因改写介绍角度而消失。非关键说法被排除后仍保留缺口和相关警告，由 Supervisor 判断是否可交给 Content。

研究问题及必需章节均有充分依据、必要搜索均已尝试且没有未解决缺口时，报告为 `completed`；有有效报告但仍有缺口时为 `partial`。可选视频失败但不影响问题和章节时可 `completed`，保留真实失败记录和警告。执行故障及取消由宿主记录，不伪造报告掩盖故障，也不将合法 `partial` 当成执行失败。

## 补查与停止

`supplement` 只补查用户明确授权的问题和缺口，以同任务、同 attempt、同项目当前采用的完整报告为基础；输出更新后的完整报告，保留原证据并记录新增、修正、撤回和缺口变化。不跨 attempt 采用旧报告。

一轮研究执行失败后，宿主结束整个 attempt；人工重新执行时沿用原选题和原榜单依据，重新授权并从头研究，本 Skill 不自行开启新轮次。工具单次失败是否影响整轮，仍按实际会话状态和有效报告判断；不把每次工具失败都当成整个研究失败。

受限工具自身不自动重试；只有在当前会话仍有效、授权范围及剩余额度允许时，Research 才可决定再次调用网页工具。会话已因超时或取消结束后不得继续重试。格式纠正只处理已有输出，不能重新取证；超限显式失败。
